# Keep a notebook you can find things in

A journal tells you what happened on a particular day. A notebook helps you do something again. Both are useful, but they answer different questions.

“Today I built my first page” belongs in the journal. “How to start my website” belongs in the notebook, where you can improve it whenever the instructions change.

## Give each note one job

A good note does not have to be long. Try three parts:

1. Say what the note helps you do.
2. Write the steps or example that worked.
3. Explain how to tell whether it worked.

For example, create `content/wiki/start-my-site.md`:

```markdown
# Start my website

Open a terminal in my-personal-site and run:

    ttrek run -script start

Open http://localhost:8080. I should see my homepage.
Keep the terminal open while browsing. Ctrl-C stops the server.
```

After a restart, the page appears at `/wiki/start-my-site`. Tomorrow's you no longer has to remember the command.

## Organize only when it helps

A handful of notes can live together. When a subject grows, give it a folder. A file named `content/wiki/projects/weather-tool.md` appears at `/wiki/projects/weather-tool`.

Use short, descriptive filenames. They become the links you share. If you improve a heading later, keep the filename so those links still work.

## Keep a way back

Your words live in Markdown files. Copy the project somewhere safe, or use Git to record changes. Think of a Git commit as a labeled checkpoint: “Added setup instructions” is easier to find later than a pile of files called `final-2` and `final-really`.

Deleting a file removes its page the next time you start the server. There is no browser revision history in this example, so a backup or a commit is how you keep earlier writing.

A useful notebook grows through small corrections. When a step confuses you, fix it while the answer is fresh.
